# FOODTOR

Интернет-магазин продуктов: сайт магазина на **HTML/CSS/JS** (страницы собирает **FastAPI** — их видят Яндекс и Google),
админка на **Flutter Web**, **PostgreSQL**, **Docker + Caddy**.

| | Демо | Сервер на своём компьютере | Релиз на VPS |
|---|---|---|---|
| Данные | демо-данные (71 товар, отзывы, заказы) | настоящая база, стартует **пустой** | PostgreSQL, стартует **пустой** |
| Адрес | http://localhost:8765 | https://….lhr.life + постоянная ссылка на GitHub Pages | свой домен |
| Вход в админку | логины из `DEMO_ACCOUNTS.md` | владелец создаётся при первом запуске | скрипт `create_owner` |
| Запуск | `./scripts/demo.sh` | `./scripts/server.sh` | `./scripts/build_release.sh` → `./scripts/deploy.sh` |

**Устройство сайта магазина** (`backend/app/web`): каталог, категории, поиск и карточки товаров — HTML с сервера
(шаблоны Jinja2, микроразметка schema.org, sitemap.xml, robots.txt, канонические адреса). Корзина, оформление с картой
(Leaflet + OpenStreetMap), вход по SMS/email и личный кабинет — небольшие JS-модули без сборщиков и фреймворков.
Refresh-токен сайта хранится в HttpOnly-cookie (недоступен JavaScript), строгая CSP без inline-скриптов.

## Сервер на своём компьютере

```bash
./scripts/server.sh
```

Скрипт поднимает базу (PostgreSQL из pip-пакета), API, Caddy (если установлен) и бесплатный SSH-туннель localhost.run
(через системный прокси/VPN, если он включён): магазин получает публичный https-адрес вида `https://….lhr.life`. Адрес меняется при каждом запуске, поэтому скрипт сразу
публикует его в ветку `gh-pages` — по постоянной ссылке **https://habibullo155.github.io/foodtor/** покупатели всегда
попадают в текущий магазин. После Ctrl+C там показывается «магазин временно недоступен».

- Один раз включите Pages: GitHub → Settings → Pages → Source: *Deploy from a branch*, ветка `gh-pages`.
- При первом запуске скрипт спросит email и имя владельца и создаст его (пароль вводится скрыто).
- Настройки — `backend/.server-data/server.env` (создаётся из `backend/server.env.example`): ключ SMS.ru для входа
  покупателей, телефон и почта магазина. Без ключа SMS.ru покупатели не смогут войти по номеру.
- Данные (база, фото товаров, ключ подписи сессий) — в `backend/.server-data`, в git не попадают. Делайте копию папки.
- Компьютер должен быть включён и не уходить в сон, пока магазин работает.

## Релиз на VPS

**1. Сервер.** Ubuntu 22.04+ с Docker, открыты порты 80/443. DNS: `A`-записи `shop.example.ru` и `admin.shop.example.ru` → IP сервера.

**2. Настройки** (один раз, на сервере):

```bash
ssh user@server 'mkdir -p /opt/saasshop/deploy'
scp deploy/.env.example user@server:/opt/saasshop/deploy/.env
ssh user@server 'nano /opt/saasshop/deploy/.env'   # домены, пароли (команды генерации — внутри файла)
```

**3. Сборка админки и выкладка** (с вашего компьютера; сайт магазина выкладывается вместе с бэкендом):

```bash
SHOP_NAME="Свежая лавка" SUPPORT_PHONE="+7 (999) 000-00-00" SUPPORT_EMAIL=help@shop.ru ./scripts/build_release.sh
./scripts/deploy.sh user@server
```

Caddy сам выпустит HTTPS-сертификаты; миграции БД применяются при старте API.

**4. Первый владелец:**

```bash
ssh user@server 'cd /opt/saasshop && docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env exec api python -m scripts.create_owner --email you@shop.ru --name "Имя Фамилия"'
```

Пароль спрашивается скрыто. Дальше — в админке: категории, товары (вручную или импорт `.xlsx`/`.csv`), уровни лояльности, сотрудники.

### Подключение оплаты (Альфа-Банк)

1. Заключите договор интернет-эквайринга, получите логин/пароль **API-пользователя** (`…-api`) для тестового стенда.
2. Пропишите в `deploy/.env`: `ALFA_USERNAME`, `ALFA_PASSWORD`, `ALFA_API_URL=https://alfa.rbsuat.com/payment/rest`, перезапустите (`deploy.sh`).
3. В личном кабинете мерчанта укажите URL уведомлений: `https://shop.example.ru/api/v1/payments/alfa/callback`.
4. Проверьте оплату тестовыми картами банка; затем смените `ALFA_API_URL` на `https://pay.alfabank.ru/payment/rest` и боевые ключи.

Пока ключей нет — онлайн-оплата скрыта ошибкой «недоступна», работает «при получении».

### Зона доставки и курьеры

- **Админка → «Доставка и оплата»**: точка склада на карте, радиус (1–100 км) и список городов, куда возим целиком.
  Адрес вне зоны: покупатель сразу видит «Мы не доставляем по вашему адресу» и предложение самовывоза; сервер
  дополнительно отклоняет такой заказ (409). Геокодер — Nominatim (OSM) по умолчанию; для нагрузки укажите
  `YANDEX_GEOCODER_KEY` в `deploy/.env`. Сбой геокодера заказ не блокирует.
- **Курьер** (роль «Курьер», создаётся в «Сотрудники»): раздел «Доставка заказов» — берёт отправленный заказ, ведёт
  чат с покупателем. Телефон покупателя скрыт, пока курьер не ближе 1 км к адресу (по GPS браузера) или пока он не
  нажмёт «ЧП» с причиной — причину увидят покупатель и магазин. Телефон курьера покупателю не показывается никогда.

### Безопасность

**Вход и сессии.** Argon2id; блокировка email на 15 минут после 5 ошибок (одинаково для несуществующих адресов —
нельзя узнать, зарегистрирован ли email); лимиты по IP (вход, коды, расчёт заказа, геокодер); запрет простых паролей;
SMS/email-коды хранятся как HMAC, 5 попыток, 5 минут. Refresh-токен сайта — в HttpOnly + SameSite=Strict cookie,
ротация с защитой от повторного использования (повтор в первые 30 с — обрыв сети, позже — кража: все сессии
закрываются). Смена пароля и «выйти везде» мгновенно гасят все выданные токены.

**Сайт.** Строгая CSP без inline-скриптов, запрет встраивания (clickjacking), HSTS, nosniff, COOP; весь вывод
экранируется (шаблоны и JS); адрес «вернуться после входа» — только на свой сайт; canonical/sitemap берут адрес
из настроек, а не из заголовка Host; в проде запросы на чужие домены отклоняются (TrustedHost).

**Данные.** Права проверяются на сервере для каждого действия (покупатель видит только свои заказы/адреса,
курьер — только свои доставки, телефон покупателя скрыт до приезда); загруженные фото проверяются и пересохраняются
в WebP без метаданных, «бомбы» отклоняются; экспорт в Excel/CSV экранирует формулы; XLSX читается через defusedxml;
статус оплаты — только из API банка с проверкой суммы.

**Инфраструктура.** API и БД не торчат наружу (только Caddy 80/443), контейнер без root, в образ не попадают
локальные данные (`.dockerignore`), тела запросов ≤ 12 МБ, документация API закрыта в проде, ошибки — без
внутренностей и по-русски. В проде сервер **не стартует** с JWT-секретом короче 32 символов или адресами без https.
CI проверяет зависимости на известные уязвимости (`pip-audit`).

**Рекомендации после запуска:** включите двухфакторный вход для сотрудников (следующий шаг доработки), настройте
бэкапы вне сервера, раз в месяц обновляйте зависимости (`pip-audit` подскажет).

### Вход по номеру телефона (SMS)

Покупатель вводит номер → получает 6-значный код → (если номер новый) указывает имя. Пароль не нужен.
Провайдер — [SMS.ru](https://sms.ru): `SMS_PROVIDER=smsru`, `SMSRU_API_ID=…` в `deploy/.env` (стоимость SMS
по тарифу SMS.ru). Защита: только мобильные номера РФ, код живёт 5 минут и хранится как HMAC, 5 попыток ввода,
повтор не чаще раза в минуту, не больше 5 кодов в час на номер и 10 с одного IP. В разработке (`SMS_PROVIDER=console`)
код пишется в лог и показывается в форме.

### Вход по коду на email (SMTP)

Покупатель может войти без пароля: email → код из письма → (новый адрес) имя; при этом почта считается
подтверждённой. Вход по паролю остаётся («Войти по паролю»). Укажите `SMTP_HOST`, `SMTP_PORT`,
`SMTP_SECURITY` (`ssl`/`starttls`), `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` в `deploy/.env`.
Чтобы письма не попадали в спам — настройте для домена SPF, DKIM и DMARC у почтового провайдера.

### Бэкапы

Сервис `backup` раз в сутки делает `pg_dump` в `/opt/saasshop/deploy/backups` (хранит 14 дней).
**Копируйте их за пределы сервера** (S3 / другой хост). Восстановление:
`gunzip -c shop-ДАТА.sql.gz | docker compose … exec -T db psql -U shop -d shop`.

## Разработка

```bash
# API (нужен PostgreSQL; для тестов — pip install pgserver, Docker не нужен)
cd backend && cp .env.example .env && pip install -r requirements.txt
alembic upgrade head && uvicorn app.main:app --reload

# Flutter
cd frontend
flutter run -d chrome -t lib/main_client.dart --dart-define=APP_MODE=demo   # магазин, демо
flutter run -d chrome -t lib/main_admin.dart  --dart-define=API_URL=http://localhost:8000   # админка на API
```

**Тесты:** `cd backend && pytest` (интеграционные — на настоящем PostgreSQL через pgserver) ·
`cd frontend && flutter test --dart-define=APP_MODE=demo test/demo && flutter test test/release`.
CI (`.github/workflows/ci.yml`) гоняет линтер, тесты, проверку миграций и сборку на каждый push.

## Архитектура

```
backend/app
├── api/v1/        auth (регистрация, JWT, /me) · catalog (товары, категории, отзывы, рекомендации)
│                  orders (расчёт, оформление, оплата) · payments (возврат/колбэк банка) · admin/*
├── services/      pricing (опт/розница) · cart · checkout (доставка, промокоды) · orders
│                  recommendations (гибрид) · payments (Альфа-Банк) · import_export (pandas) · bootstrap
├── models/        пользователи/роли/права · товары/связи · заказы/оплата · прайс-листы · лояльность · промокоды
└── alembic/       миграции (начальная — вся схема + pg_trgm)
frontend/lib
├── core/          config (APP_MODE, API_URL) · network (Dio + refresh) · theme (светлая/тёмная) · responsive
└── features/      home · catalog · cart · account · admin · stories · legal · loyalty
```

**Рекомендации** («С этим часто покупают»): `3·ручные связи + 2·совместные покупки/√популярность + 0.3·популярность`,
не больше 2 товаров одной категории. «Похожие» — ручные upsell, иначе та же категория дороже в 1–1.8 раза.

**Безопасность:** Argon2id; JWT access 15 мин + refresh с ротацией и детектом кражи; RBAC по правам на каждом
эндпоинте; rate limit (вход — 5/мин); Pydantic на всех входах; только ORM/bind-параметры; цены и итоги считает
только сервер; статус оплаты — только из API банка (не из редиректа) со сверкой суммы; CSP/HSTS в Caddy;
БД и Redis не торчат наружу.
